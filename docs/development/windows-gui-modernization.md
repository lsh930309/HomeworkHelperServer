# Windows PySide6 Widgets 실행·검증 계약

## 단일 실행 경로

Windows GUI는 **PySide6 + Qt Widgets**만 사용한다. MainWindow를 직접 생성하고
tray·IPC·알림도 같은 창을 표시한다. 사이드바·볼륨·스크린샷·녹화·정상 종료를 유지한다.
QML 후보 화면·Facade·투영·타이머·엔진·대체 창 포인터와 renderer 옵션 및 환경변수를
제거한다. 선택기·호환 분기·자동 복귀는 남기지 않는다.

PySide6는 Qt 6의 Python 바인딩이다. 필요한 Core·Gui·Widgets·Network를 유지하며
QML·Quick은 패키지에서 고정 제외한다. 새 프레임워크는 도입하지 않는다.

## 런타임과 패키징

- Python 3.14, PySide6==6.11.1의 깨끗한 환경과 PyInstaller onedir·Inno Setup을 유지한다.
- PyQt6 동시 설치 거부와 제품의 PyQt/sip 의존성 금지 검사는 유지한다.
- 신규 heartbeat·API 기본값·진단은 pyside6와 widgets로 통일한다. 기존 기록은 재작성하지 않는다.
- 후보 빌드 옵션·테스트·활성 PyQt 표기는 제거하고 Qt Network의 단일 인스턴스 IPC는 유지한다.
- GUI 종료는 MainWindow에서 native filter·timer·tray·sidebar·녹화·follow-up·worker를 정리한다.
- 명시적인 앱 종료는 정리 완료 후 GUI 스레드에서 `QApplication.exit(0)`으로 실행 루프를
  반환시킨 뒤 기존 API child 종료 절차로 이어진다. 창 닫기의 트레이 숨김 정책이 이 종료를
  취소하지 않으며, IPC ACK는 요청 수락이고 GUI/API 프로세스의 종료 완료는 별도로 확인한다.
  표시·네이티브 최소화·숨김 상태와 트레이·IPC 진입을 실제 Qt 실행 루프와 격리 child로 검증한다.

## 네이티브 복귀와 실기기 검증

QAbstractNativeEventFilter는 PySide6의 QByteArray/bytes 실제 값으로 이벤트 이름을
해석한다. 실제 MSG의 WM_POWERBROADCAST와 복귀 코드 0x12를 기존 복귀 처리와
API·감시·출석 후속 갱신에 연결한다. 별도 복귀 상태는 저장하지 않는다.

합성 메시지는 실제 Windows QPA/MSG 경계를 검증한다. 물리 절전·복귀는 운영 GUI 로그와
OS 이벤트를 함께 확인하고 [호스트 계약](windows-host-lifecycle.md#과거-전원-진단-계약)의
마지막 단계에서 수행한다. offscreen·합성 메시지·사용자 데스크톱 검수는 구분한다.
Widgets 시작, tray 숨김·복원, IPC/알림, sidebar·volume·screenshot·recording·종료 중
late callback을 직접 관련 자동 검증과 실제 Windows로 확인한다.
테스트 Python 자식과 부모 수집은 UTF-8로 맞추며 디코딩 오류를 조용히 치환하지 않는다.

## 사이드바 표시 계약

배치 작업은 [UI 작업 규칙](../../AGENTS.md#ui-배치스크롤-작업)의 목업·비율·스크롤 우선순위를 따른다.
현재 사이드바 너비 구현은 280 논리 픽셀이다. 긴 게임 이름은 주어진 이름 영역 안에서
줄바꿈하며 스크롤 내용 전체의 최소 너비를 늘리지 않는다. 창 바로가기·실행/종료·원형 음량과
촬영·녹화 버튼은 내용 넘침 여부와 관계없이 우측 경계 안에 들어가야 한다.
기존 전체 내용 영역의 가로·세로 스크롤바는 표시하거나 공간을 예약하지 않는다.
내용이 작업 영역보다 길어지는 경우에도 휠 스크롤과 하단 닫기 버튼 접근은 유지한다.

등록 게임과 음량은 하나의 목록으로 합치고 메인 GUI와 같은 게임명 오름차순으로 표시한다.
정렬 키는 `ManagedProcess.name_sort_key` 한 곳에서 계산한다. 이름은 `casefold()`로 비교하고,
이름이 같으면 등록 ID로 순서를 고정한다. 실행 시각·등록 순서·실행 여부는 정렬 기준이 아니다.
이름 수정·실행 대상 변경 후 기존 콘텐츠 갱신에서 다시 정렬하며 원본 등록 목록이나 실행 캐시를
재배열하지 않는다. 종료 버튼의 등록 ID·PID·생성 시각과 음량의 등록 대상·PID 연결은 유지한다.
게임 아이콘 오른쪽에는 이름, 실행 중에만 보이는 창 바로가기, 실행/종료 한 개, 원형 음량을
순서대로 둔다. 미실행 게임에도 실행 버튼과 저장 음량을 표시한다. 실행 중인 모든 행은
파란 반투명 배경과 아이콘의 녹색 테두리로 강조하며 실행 여부는 기존 감시만 소유한다.

실행은 메인 GUI와 같은 대상·추가 인자 계산과 `Launcher`의 권한 정책을 사용한다.
GUI에서 확정한 입력으로 백그라운드 작업을 제출하고 앱 종료·DB 복구 후 대기 작업은 실행하지
않는다. 일반 권한 런처의 재시작에 사용자 확인이 필요한 경우 사이드바에서 자동 종료하지
않으며 기존 실행 정책의 거부를 로그에 남긴다. 창 바로가기는 지정 PID·생성 시각·경로·사용자
세션을 확인하고 현재 표시 중인 게임 창을 복원·활성화한다. Windows가 포커스를 거부하거나
게임 창이 아직 없으면 로그에 남기고 사이드바를 유지한다. 가짜 입력·SYSTEM 활성화·재전송은
추가하지 않는다. 창 전환 성공 때만 사이드바를 닫는다.

스크린샷·녹화의 파일 미리보기는 하나의 공용 갤러리로 표시한다. 시계 → 통합 게임·음량 →
촬영 → 녹화 조작 → 파일 종류 선택 → 공용 갤러리 → 닫기 순서를 유지한다.
파일 종류 선택은 현재 창의 UI 상태만 소유하며 설정·DB에는 저장하지 않는다. 선택을 바꿔도
촬영·녹화 조작부는 바뀌지 않는다. 녹화 조작 활성화와 기존 녹화 파일 조회 활성화는 독립이다.

사용자가 선택한 Acrylic 통합 목록 목업을 기준으로 배치한다. 시계와 날짜·요일은 스크롤 밖의
최상단, 닫기는 최하단에 고정한다. 통합 게임·음량 목록은 상단에, 촬영·녹화 행과
파일 종류 선택·공용 갤러리는 하단에 붙인다. 여유 높이는 두 묶음 사이에 배분하며
갤러리 안에 빈 공간으로 남기지 않는다. 긴 게임 이름만 줄바꿈한다.
촬영과 녹화는 각각 한 행으로 구성하고 녹화 상태·해당 상태의 조작 버튼도 같은 행에 둔다.
파일 선택 탭은 조작 버튼과 같은 둥근 모서리를 사용하고 두 탭 사이의 간격을 둔다.
간격·패딩·음량 열과 아이콘 크기는 사이드바의 가용 너비 비율로 계산한다.
음량 헤더는 게임 행과 같은 오른쪽 여백·열 너비를 사용하고 음량 원의 가로 중심에 맞춘다.
게임 행의 조작부는 부모 레이아웃에 붙인 뒤 표시하여 열기·갱신 중 독립 창으로 나타나지 않는다.
창 전환·실행/종료 버튼과 음량 원의 외곽 크기는 같은 정사각형이다. Qt 스타일 적용 후에도
최소·최대 크기가 일치해야 하며 텍스트 버튼용 최소 높이·좌우 패딩이 이 조작부에 적용되지 않는다.
미실행 행에는 빈 창 전환 슬롯을 예약하지 않고 게임 이름에 돌려준다. 게임 이름은 보조 상태보다
밝은 본문 색과 약 4.3% 너비의 글자 크기를 사용하고 아이콘은 약 10.7%, 조작부는 약 11.4%다.
구분선은 가는 선과 위아래 여백을 함께 소유하여 두 섹션에서 같은 간격을 유지한다.
시계·플레이타임·음량 조작부의 표시 설정은 유지한다. 시계는 HH:MM과 오른쪽 아래의 작은
SS를 사용하고 초 앞 콜론은 두지 않는다. 콜론의 두 점은 숫자 획의 세로 중심에 맞추고 실제
시각의 0.5초 경계마다 표시/숨김을 전환한다. 기존 시계 타이머를 사용하며 숨김 때 멈춘다.

음량은 0~100% 원호와 스피커 아이콘으로 표시한다. 휠 한 단계는 5%이며 키보드 위/아래도
같은 단위를 쓴다. 조정 중에는 아이콘에서 수치로 180ms 동안 전환하고 마지막 조정 900ms
뒤 아이콘으로 돌아간다. 클릭은 수동 음소거만 전환하고 저장 음량은 지우지 않는다.
수동 음소거 또는 음량 0이면 음소거 아이콘이다. 0에서 올려도 수동 음소거는 유지한다.
미실행 게임에는 기존 저장 기본값을, 실행 게임에는 조회된 실제 오디오 값을 사용하며 조회
불가 때만 저장값을 사용한다. 조정은 기존 오디오 writer와 500ms 저장 디바운스를 공유한다.
화면 갱신 자체는 음량을 쓰지 않는다. 행 교체·숨김·앱 종료 때 표시 타이머와 애니메이션을 정리한다.

전체 창 opacity는 1이며 배경만 고정된 검은 반투명 색과 Acrylic을 사용한다. 글자·아이콘은
함께 흐려지지 않는다. 시계와 게임, 게임과 하단 미디어 사이에는 얇은 구분선을 두고 녹화에는
비디오카메라 아이콘을 사용한다. 자유 형식 시계·투명도·효과 선택을 활성 렌더링 경로에서
사용하지 않는다. 과거 DB 열은 파괴적 마이그레이션 없이 유지하되 새 설정 writer는 변경하지 않는다.
포커스를 받지 않는 도구 창에서 Background Acrylic의 비활성 단색 정책을 사용하지 않는다.
기존 accent Acrylic 호출을 Windows 10 1809 이상에서 공통 사용하고, 고정 검은 tint는 그 호출에서
한 번만 적용한다. 성공한 native 배경 위에 Qt의 어두운 불투명 막을 다시 덮지 않는다. 미지원·호출
실패 시에는 같은 고정 tint 배경을 사용하고 실패를 로그에 남긴다. Windows 설정·게임 포커스를
변경하지 않는다. accent policy는 Windows의 비공개 확장 경계이므로 API 반환 성공과 실제 합성
품질을 구분한다. 이번 수정의 실제 합성 품질은 사용자 Windows 검수 전까지 미검증이다.

메인 게임 표·음량 팝업·사이드바 게임 아이콘은 같은 `GameIconLabel`을 사용한다. 원본 아이콘·캐시는
변경하지 않고 표시 슬롯의 중앙 정사각형을 약 20% 반경으로 잘라 그린다. 테두리만 둥글게 그려
원본 이미지 모서리가 남는 경로는 두지 않는다. 실행 강조 테두리도 같은 슬롯에서 그린다.

필수 조작부를 배치한 뒤 가용 높이와 파일 수에 맞게 갤러리를 최대 3행으로 제한한다.
셀 너비는 가용 너비의 3분의 1,
높이는 너비의 3/4로 계산하며 간격도 가용 너비에 비례한다. 높이에 들어가는 1~3행만
표시하고, 최신 파일 2·5·8개와 마지막 폴더 버튼을 배치한다. 폴더 버튼의 `+N`은 현재
미리보기에서 생략한 모든 파일 수다. 파일이 없어도 폴더가 존재하면 폴더 버튼은 유지한다.
촬영 완료·녹화 경로 변경·파일 삭제·창 재진입에서는 같은 선택의 파일 목록을 갱신한다.
갤러리는 콘텐츠 갱신 때 최신 파일 최대 8개의 셀과 폴더 버튼을 준비한다. 크기 변경은
기존 셀의 크기·노출 행만 바꾸며 폴더 조회·정렬·버튼 재생성·디코딩을 다시 수행하지 않는다.
노출하지 않는 셀은 숨기고 공간을 차지하지 않으며 폴더 버튼의 생략 수에 포함한다.
같은 파일·셀에 도착한 썸네일은 크기 변경 뒤에도 적용할 수 있다. 종류·경로·콘텐츠 갱신
이전의 응답은 기존 요청 ID로 차단한다. 추가 감시 타이머나 파일 목록 저장소는 만들지 않는다.

열기·닫기 애니메이션의 완료 처리는 하나이며 현재의 열기/닫기 의도만 소비한다.
닫는 중 다시 열어도 이전 닫기의 완료가 새 창을 숨기지 않는다. 전환 중 화면 밖 좌표를
포인터 이탈·외부 클릭으로 판단하지 않으며, 완료 이후 기존 자동 숨김 설정을 적용한다.
저장된 음량 0은 무음 값으로 유지하며, 값이 없는 경우에만 100을 기본값으로 표시한다.

작업 표시줄이 나타나 높이가 줄면 우선 갤러리 행 수를 줄여 전체 스크롤을 피한다.
1행과 필수 조작부도 들어가지 않는 극소 높이에서는 가운데 내용의 숨김 휠 스크롤로
모두 접근한다. 이때도 시계와 닫기는 고정한다.
이 변경은 기존 창 너비·작업 영역 판정·파일 저장 경로·촬영·녹화 실행 계약을 바꾸지 않는다.

동작 실패의 상세 원인은 GUI 로그에 기록한다. 게임 종료 작업의 결과 문구와 OBS 오류
툴팁을 사이드바에 투영하지 않는다. 녹화 연결 상태·녹화 시간 같은 짧은 정상 상태는
유지하며, 종료 요청 수락을 실제 게임 종료로 취급하지 않는다. 실제 종료 판정은 기존
프로세스 감시가 소유한다.

높이와 우측 위치는 해당 모니터에서 실제로 보이는 작업 표시줄을 제외한 영역으로 계산한다.
보이는 일반 작업 표시줄의 두께는 Windows의 공식 작업 영역을 사용한다. 작업 표시줄
창 외곽의 투명 여백까지 제외하지 않는다. 예약 영역이 없는 자동 숨김 표시줄이 펼쳐지면
보이는 표시줄의 영역을 제외한다.
전체 화면이 작업 표시줄을 가리거나 자동 숨김으로 숨겨져 있으면 모니터 전체 영역을 사용한다.
사이드바 자신의 창이 작업 표시줄을 덮어도 숨김으로 오판하지 않는다. 표시 중에는 기존
커서 확인 타이머에서 영역을 다시 계산하며 별도 전체 화면 상태나 타이머를 저장하지 않는다.
기존 높이 비율은 이 영역에 적용한다. Windows 물리 좌표는 해당 모니터의 Qt 논리 좌표로
변환하고, OS 조회 실패 시 Qt가 제공하는 작업 영역을 사용한다.
모니터는 표시 이름이 아닌 원점으로 연결한다. Windows에서는 Qt가 모니터 크기를 DPI에
맞춰 변환하되 원점은 유지한다([Qt 좌표 계약](https://doc.qt.io/qt-6/highdpi.html#device-independent-screen-geometry)).
작업 표시줄 후보는 클래스별 `FindWindowEx`로 직접 조회한다. 전체 화면에서 시작 메뉴를
열면 `EnumWindows` 목록에서 표시 중인 작업 표시줄이 누락되는 실호스트 재현이 있어,
일반 앱 창 열거 목록을 작업 표시줄의 존재 판정으로 사용하지 않는다.
사이드바의 대상은 현재 주 모니터다. Apollo가 가상 모니터를 주 모니터로 만들고 다른
모니터를 비활성화하는 전환에서도 생성·추가·제거 이벤트가 같은 선택 기준을 사용한다.

## 메인 창 표시·자유 이동·경계 흡착

트레이 클릭·게임 실행 감지·최소화 버튼·닫기의 숨김은 같은 TrayManager 경계를 사용한다.
Windows에서는 창을 `hide()`로 제거하지 않고 네이티브 최소화 상태를 유지하며
`ITaskbarList.DeleteTab`으로 작업 표시줄 버튼만 제거한다. 최소화 이벤트가 버튼 제거를 소유하고,
복원은 `AddTab` 뒤 같은 창의 `showNormal()`을 사용한다. 트레이·IPC·알림은
`activate_and_show()`로 복원한다. 기본 전환은 Windows가 소유하며 임의 지연·별도 애니메이션
상태를 추가하지 않는다. 앱 프로세스·트레이·감시는 유지한다. Shell 호출 실패는 로그에 남기며
실패를 숨기려고 창을 즉시 숨기거나 프레임 스타일을 바꾸지 않는다.
Shell 버튼 제어는 [Windows ITaskbarList 계약](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-itaskbarlist)을 따른다.

코드·격리 Qt 상태 전이 검증은 실제 DWM 애니메이션과 구분한다. 기본 전환의 시각적 성공과
작업 표시줄 버튼 제외는 실제 Windows 사용자 검수 이후에 판정한다.

메인 창과 사이드바는 같은 Windows 가시 작업 영역 계산을 사용한다. 메인 창을 열 때는
커서가 있는 모니터를 선택하여 보이는 DWM 프레임의 우측 하단을 맞춘다.
표시 이후에는 자유롭게 이동할 수 있다. 드래그로 가시 프레임이 작업 영역의 상하좌우
경계에서 15 논리 픽셀 이내로 가까워졌을 때만 해당 축을 붙이며 크기는 바꾸지 않는다.
콘텐츠 크기 변경·주 모니터 전환·주기 갱신은 현재 위치를 유지하고, 작업 영역 밖으로
나간 부분만 안으로 보정한다. 이 경로에서 우하단 정렬을 다시 강제하지 않는다.
표시·근접 스냅·영역 내부 보정은 같은 순수 사각형 계산과 하나의 Windows 이동 경계를 쓴다.
모니터 선택은 Qt 좌표로 수행하고 Windows 조회에는 모니터 원점을 전달하여 DPI가 다른
화면에서 논리 커서 좌표를 물리 좌표로 오해하지 않는다.

작업 표시줄의 표시·가림 변화는 기존 메인 GUI 표시 갱신 타이머에서 재확인한다.
숨겨지거나 최소화된 메인 창은 이동시키거나 표시하지 않는다. 이미 목표 위치이면 네이티브 이동을
요청하지 않는다. OS 조회 실패 시 Qt 작업 영역에 동일한 표시·스냅·보정 계산을 적용한다.
창 위치를 저장하거나 별도 작업 영역 상태·감시 타이머를 추가하지 않는다.

구분한다. 실화면 검수는 사용자가 담당한다.
