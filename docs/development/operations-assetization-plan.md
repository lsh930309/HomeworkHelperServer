# 문서·정책과 반복 작업의 중앙 자산화 계획

상태: 자료 조사와 초기 계획 작성. 문서·도구 재편은 다음 단계이며 제품 동작과 운영 설치본은 변경하지 않았다.

## 목표와 보존 조건

문제 진단·검증·빌드·배포 때마다 과거 대화를 찾거나 임시 프로그램을 다시 만드는 비용을 줄인다.
작업자는 관련 계약과 기존 도구를 먼저 읽고, 검증된 공용 경로로 작업하며, 새로 확인한 반복 절차는 같은
소유 문서·도구에 반영한다. 사용자가 같은 지침을 매번 다시 전달할 필요가 없어야 한다.

`build.py`의 빌드·서명·패키징·버전·아카이브·정리 소유권, 일반 권한 앱과 권한 서비스의 분리,
DB·자격 증명 테스트 격리, 사용자 중심 오류 보고, 사용자 담당 실화면 검수를 유지한다.
멀티에이전트는 사용하지 않는다. 배포 자동화가 호스트 조작 권한이나 시간 제한을 대신하지 않는다.

작업 브랜치는 `docs-and-policies`이며 기존 로컬 `main`의 `fb92714`에서 생성했다.
이 기준점에는 GitHub `origin/main`보다 앞선 기존 6개 커밋이 포함된다. 문서 작업 때문에 기존
커밋을 재작성하거나 삭제하지 않는다. 이번 조사에서는 원격 푸시·호스트 조작·빌드·배포를 수행하지 않는다.

그대로 승격하거나, 임시 스크립트를 검토 없이 통째로 편입하지 않는다.

필수 문서를 무조건 늘리기보다 다음 두 개를 추가하고 기존 소유 문서를 갱신한다.
아래 신규 경로는 제안이며 이번 단계에는 이 계획 문서만 작성한다.

| 문서 | 소유할 내용 |
|---|---|

| `docs/guides/operations-guide.md` — 신규 | 반복 작업 도구 목록, 실행 조건·입출력·부작용·관련 검사, 공용 도구 유지관리 방식 |

각 사실은 위 소유 문서 한 곳에서만 정한다. `README.md`와 문서 색인은 링크를 제공한다.
도구의 옵션·동작은 구현과 일치해야 하며 사용 예시는 그 도구의 소유 문서에서 유지한다.
사건별 오류·해결 기록은 기존 이슈·PR에 보존하고 활성 운영 문서에는 재사용할 계약과 명령만 남긴다.
이 계획도 편입 완료 후 활성 계약에 흡수하고 제거한다.

## 중앙 자산화 우선순위와 범위

1. **읽기 전용 상태 수집·문제 분류**
   - 로컬/원격 Git 지점, Windows 빌드 지점, 설치 버전, 서비스·앱·OBS의 사용자/세션/권한,
     API 생존·DB 준비·감시 로그를 한 번 수집하고 필요한 부분만 요약한다.
   - 연결 무응답, 앱 인증 실패, DB 장애, 권한 서비스 오류를 구분한다. DB 초기화나 설정 변경을
     일으키는 제품 모듈 import를 상태 조회에 사용하지 않는다. 비밀번호·토큰·개인키는 출력하지 않는다.
2. **소스 준비·Windows 빌드·패키지 설치의 반복 절차**
   - 배포가 승인된 작업은 관련 검증·커밋·해당 브랜치 푸시 후 Windows에서 공개된 정확한 커밋을
     가져오는 흐름을 기본으로 한다. Git bundle 직접 전달은 명시적인 로컬 배포 예외에 한정한다.
   - 빌드는 기존 `build.py` 호출만 담당한다. 패키지 복제·수동 서명·임의 재포장을 추가하지 않는다.
   - 기존 정상 백업, 종료 IPC, OBS 잠금 확인, Setup, 일반 사용자 세션 실행, 서명·payload·API
     확인 코드를 선별 편입한다. 정상 종료 실패·백업 실패·설치 실패에서 다음 단계를 실행하지 않는다.
   - 소스 커밋 공개, 빌드 성공, 설치 성공, 로그/API 확인, 사용자 실사용 검수를 각각 구분한다.
3. **격리 검증과 사용자 세션 진단**
   - `ssh_host_testbench.py`는 기존 격리 API 시험 범위를 유지한다. 운영 설치·서비스 등록 도구로
     확대하지 않는다. `run_remote_powershell`의 UTF-8 strict·반환 코드 처리 경계를 재사용한다.
   - 실제 권한·pipe·프로세스·Windows 메시지 검증은 관련 기존 테스트를 Windows에서 실행한다.
     macOS 인증 시험은 별도 preferences/cache와 명시적 `InMemoryTokenStore`를 사용한다.
   - 세션·권한 또는 창 이벤트가 실제로 문제를 설명할 때만 해당 진단을 사용한다.
     단순 상태 조회가 창 활성화·게임 실행·촬영·녹화·전원 조작으로 이어지지 않는다.

실행 코드는 기존 `tools/`에 둔다. 기존 CLI가 같은 책임을 소유하면 그곳을 보완하고, 책임이 다르면
운영 명령을 분리하되 공통 SSH 실행과 제품 API를 재사용한다. 구체적인 새 CLI 이름·옵션은 편입할
기존 코드의 입력·부작용·호출자를 확인한 다음 정한다. 새 서비스·예약 실행·영속 상태·자동 복구를
만들지 않으며, 자주 쓴다는 이유만으로 이미 있는 명령에 별도 wrapper를 씌우지 않는다.

## 관련 작업마다 읽고 보완하는 방식

- 작업 시작: `AGENTS.md` → 문서 색인의 관련 행 → 소유 문서 → 기존 도구의 입력·실패 동작 확인.
  모든 문서나 과거 로그를 매번 전부 읽지 않는다.
- 실행: 이미 있는 명령으로 필요한 증거만 수집한다. 정상 통과 증거는 코드·입력·관련 조건이 바뀌거나
  새로운 실패가 있을 때 재확인한다. 운영 환경 조사와 격리 테스트의 대상을 실행 전에 확인한다.
- 새 임시 작업: 기존 도구로 확인할 수 없는 구체적인 가설에만 허용한다. 확인된 반복 절차는
  관련 도구에 편입하고 소유 문서·관련 검사를 같은 변경에서 갱신한다. 가설이 탈락하면 일반 도구로
  늘리지 않는다. 사용자 업무나 제품 기능을 이 자산화 작업의 시험 대상으로 임의 사용하지 않는다.
- 완료: 실제 실행 명령·대상 커밋·결과·잔여 범위를 짧게 보고한다. 세부 로그는 기존 ignored
  `artifacts/`에 보관하며, 추적 대상 코드가 과거 artifact 경로·특정 날짜·PID·개인 인증 정보에
  의존하지 않게 한다. 공용 명령이 같은 역할을 대신한 임시 코드만 선별 정리한다.
- 비용 개선: 반복되는 수동 단계·중복 수집·불필요한 원격 왕복이 확인되면 해당 작업 범위에서
  공용 도구를 보완한다. 속도 개선은 실제 실행 시간·호출 수·반복 단계의 전후 차이로 설명한다.
  관련 없는 전체 회귀·상시 감시·주기적 자동 최적화는 추가하지 않는다.
