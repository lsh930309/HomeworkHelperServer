# 커밋 메시지 작성 정책

이 레포의 커밋 메시지는 언제 작성하더라도 **한국어, 계층 목록형, 검증 포함** 형식으로 고정한다.

## 필수 규칙

1. 제목은 한국어 요약으로 쓴다.
   - 작업 유형은 기존 대괄호 영문 접두어(`[feat]`, `[fix]`, `[docs]`, `[refactor]` 등)를 사용하고,
     뒤의 요약은 한국어로 작성한다.
   - 파일명, 모듈명, 명령어, API명 같은 고유 식별자는 필요한 경우 원문을 유지할 수 있다.
2. 제목과 본문 사이에는 빈 줄을 둔다.
3. 본문은 계층 목록으로 작성한다.
   - 최상위 항목에는 최소한 `변경 사항`과 `검증`을 포함한다.
   - 각 최상위 항목 아래에는 실제 내용을 하위 목록으로 정리한다.
4. 검증 결과를 반드시 남긴다.
   - 테스트나 빌드를 실행했다면 명령과 결과를 적는다.
   - 실행하지 못했다면 이유와 남은 확인 방법을 적는다.
5. 병합 커밋과 되돌리기 커밋도 같은 정책을 따른다.
   - 기본 Git 메시지인 `Merge ...`, `Revert ...`를 그대로 커밋하지 않는다.

## 제품 단위 커밋 규칙

- 새 버전 정책을 시작한 뒤에는 한 커밋과 한 PR에서 Windows 호스트 또는 macOS 클라이언트
  한 제품의 패키지에만 영향을 주도록 변경을 나눈다. 두 제품을 바꾸는 요청은 브랜치 분리안을
  사용자에게 먼저 알리고 동의를 받은 뒤 브랜치를 만든다.
- 제품 영향은 [패키지 입력 분류](../../tools/version_policy.py)에 따라 판정한다. 앱 코드,
  포함 리소스, 의존성, 설치·패키징 입력이 대상이다. 패키지에 포함되지 않는 문서와 테스트만
  바꾼 커밋은 제품 버전을 올리지 않는다. `build.py`는 제품별 패키징 정의와 산출물을 보관하는
  운영 정의를 구분한다. 제품을 구분할 수 없는 구조와 양쪽에 포함되는 자원은 공통 입력이다.
  두 제품에 영향이 가는 공용 입력은 제품별 변경이 가능하도록 분리한다.
- 시작 태그 `H/v1.6.0`과 `C/v1.0.0`은 같은 `main` 커밋에 둔다. 이 시작점부터
  제품 단위 규칙을 적용한다. 이후 `main`의 한 커밋에는 한 제품의 정식 버전 태그를 붙일 수 있다.
- 로컬 `pre-commit` 훅은 스테이징한 입력을 검사한다. PR 병합 명령은 각 커밋과 PR 전체의
  입력을 다시 확인한다. 개발 브랜치에 `main`을 병합하면 이미 `main`에 있는 변경은 개발 버전
  계산과 제품 검사에서 제외한다. 자동 병합 결과에 추가한 수정과 충돌 해결은 이 병합 커밋의 변경으로 센다.
  번호 부여와 릴리즈 절차는 [빌드 가이드](../guides/build-guide.md)를 따른다.

## PR 병합 승인

- 병합 전에 대상 PR의 최종 base와 head를 확인하고 전체 diff를 리뷰한다.
- 리뷰에서 확인된 문제를 모두 수정하고 관련 검증을 실행한다. 변경된 최종 diff를 다시 리뷰한다.
- 사용자에게 대상 PR, 확인한 base와 head의 SHA, 리뷰와 검증 결과를 알리고 그 PR의 병합에 대한
  명시적 동의를 따로 받는다.
- 승인받은 base와 head가 모두 일치할 때 병합한다. 어느 하나라도 달라지면 변경된 diff를 다시
  리뷰하고 그 상태를 기준으로 새 병합 동의를 받는다.
- 구현, 배포, PR 생성이나 앞선 작업에 대한 승인은 대상 PR의 병합 동의와 별개다.

## 권장 템플릿

```text
[docs] 커밋 메시지 작성 규칙을 고정한다

- 변경 사항:
  - repo-local AGENTS.md에 커밋 메시지 작성 계약을 추가한다.
  - Git hook과 검증 스크립트로 한국어 계층 목록 형식을 확인한다.
- 검증:
  - ./.venv/bin/python -m pytest tests/test_commit_message_policy.py -q 통과.
  - tools/validate_commit_message.py로 예시 메시지 검증 통과.
```

## 로컬 고정 방법

이 브랜치에서는 다음 설정으로 추적 가능한 hook과 템플릿을 사용한다.

```bash
git config core.hooksPath .githooks
git config commit.template .gitmessage
```

설정 후 `git commit`을 실행하면 `.gitmessage`가 기본 메시지 초안으로 열린다.
`.githooks/pre-commit`은 제품이 섞인 변경을, `.githooks/commit-msg`는 메시지 형식 위반을 차단한다.
